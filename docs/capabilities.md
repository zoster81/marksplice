# Marksplice Capability Matrix and Roadmap

Status: source of truth for the current product-facing read/edit/create capability surface and the completed M92–M115 roadmap record.

This document answers three separate questions for each Markdown family:

1. can Marksplice understand the construct semantically under the GFM profile;
2. can callers read a reviewed public structural representation from a parsed immutable snapshot;
3. can callers safely edit existing source or construct new canonical source through reviewed APIs.

These are intentionally different capability levels. A construct may be semantically understood and preserved without being publicly actionable. Public promotion requires reviewed source ownership, caller-facing semantics, and fail-closed behavior.

Normative Markdown behavior belongs to [`gfm-conformance.md`](gfm-conformance.md). Durable implementation and current parser/source ownership boundaries belong to [`architecture.md`](architecture.md). [`goldmark-capability-matrix.md`](goldmark-capability-matrix.md) is the historical pre-M115 parser/source transition record. Milestone-specific contracts and verification evidence belong to [`milestones/`](milestones/).

## Cross-cutting guarantees

Parsed documents are immutable source snapshots. Public `NodeID` values are deterministic only within one snapshot and are not durable identities across arbitrary revisions. Public ranges are half-open byte offsets into that snapshot, and `Document.SourceRange` returns caller-owned copies.

M97 adds bounded immutable-snapshot selectors: `Document.QueryNodes` filters promoted nodes by reviewed kind, optional containing source range, and mandatory positive result limit; `Document.QuerySections` filters the existing derived `Section` model by heading level, optional containing range, and the same explicit result bound. Query results remain in authoritative source order, are caller-owned, retain no query state, and create no persistent query index. `NodeMatch.Range()` reuses the matched kind's existing typed operation-oriented `Range()` semantics for selection only; it is not a new generic mutation span.

M98 adds native single-document navigation primitives derived from the same immutable snapshot: GitHub-compatible heading anchors with deterministic duplicate handling, exact fragment resolution across heading-derived and promoted explicit HTML anchors, deterministic TOC generation from the existing `Section` hierarchy, managed-TOC stale detection, and fail-closed source-preserving synchronization of an explicitly designated TOC-shaped section body. M98 stores no anchor/fragment index or second section tree.

M99 adds source-ordered immutable link intelligence over the same snapshot. `Document.LinkRelationships` covers parser-resolved direct/reference links, direct/reference images, and angle/bare/extended autolinks; optionally associates an existing promoted source node and uniquely proven promoted reference definition; and classifies local `#fragment` destinations through the exact M98 resolver. Other-document paths and URLs remain opaque data. M99 retains no relationship/definition/fragment graph index: ephemeral maps make enumeration expected O(N+H+R) while unresolved reference-looking source is intentionally left for M101 diagnostics.

M100 adds an immutable multi-document graph over an explicit caller-provided set of already parsed documents. Callers assign opaque `DocumentKey` values and may provide a `DocumentResolver` that maps non-local M99 relationships only to keys already present in that set; Marksplice never retains the resolver or interprets keys/destinations as filesystem or network authority. Local `#fragment` relationships become self-edges without resolver calls, cross-document fragments reuse M98 target semantics, and `DocumentGraph` exposes deterministic edges, outgoing relationships, backlinks, BFS reachability, and direct related documents. Each resolved edge is stored once while adjacency maps retain only edge indices; build-local fragment resolvers reuse at most one ephemeral target catalog per cross-fragment target document.

M101 adds explicit bounded workspace validation over the same caller-provided document set. `ValidateWorkspace` classifies non-local relationships only through a build-time `WorkspaceResolver`, reuses M98/M99/M100 for fragment/document topology, reports conservative unresolved explicit references plus orphan/reachability and managed-TOC findings, and never discovers files or retains caller resolution authority. Automatic repair is limited to caller-designated, M98-recognized stale TOCs; multiple stale TOCs in one snapshot compile into one family-specific atomic `ChangeSet` rather than weakening generic M95 composition.

M102 adds GitHub alerts as a Marksplice-owned semantic overlay over already-promoted top-level blockquotes. `Alert` reuses the underlying blockquote `NodeID` and complete source ownership, recognizes only the exact reviewed `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, and `[!CAUTION]` first-line markers with non-empty body source, and exposes caller-owned body ranges without retaining an alert index. `DocumentBuilder` can construct canonical single-paragraph, typed-inline, or reviewed multi-block alerts through the existing blockquote writer/proof machinery; private construction intent prevents alert nesting without changing the baseline GFM grammar or creating a separate parser mode.

M103 adds the broader read-only `FencedBlock` model for every source-proven top-level GFM fenced container. It exposes the complete physical container, exact opening/optional closing delimiter runs, indentation, parser-proven info string and language token, and caller-owned per-physical-line payload ranges; empty and unclosed forms are represented without synthetic source. The historical `FencedCode` view remains the narrower payload-edit contract and is available only when one exact contiguous replacement span is proven. Empty construction is canonical, embedded payload languages remain opaque data, and no persistent fence index or secondary parser state is retained.

M104 adds footnotes as an explicitly reviewed core capability outside the pinned GFM 0.29 baseline. Native integrates the reviewed footnote observation pass with ordinary document parsing while keeping footnotes distinct from the normative GFM grammar; Marksplice independently proves complete top-level definition ownership, retains exact case-sensitive reference relationships/occurrences, exposes multiline semantic body ranges read-only, and grants body replacement only to the conservative single opening-line span. Coordinated rename updates one definition plus all parser-bound occurrences atomically. Canonical immediate/deferred definitions and typed references are construction-proven, `KindFootnoteDefinition` participates in M97 queries, footnote relationships participate in M95 composition proof, and ordinary links inside footnote bodies feed the existing M99/M100 relationship/graph surface. No secondary parser dependency, persistent footnote lookup, or graph index is retained.

M105 adds mathematical expressions as a Marksplice-owned GitHub-compatible source overlay while leaving the normative GFM parser profile unchanged. Dedicated source-proven `$...$`, dollar-backtick, and top-level one-line `$$...$$` forms become `KindMathExpression`; exact-info `math` fenced blocks are projected through the same M103 `NodeID` rather than duplicated structurally. Payload replacement preserves the exact form and reparses the candidate, typed/canonical construction covers the reviewed forms, and mathematical payload stays opaque. The scanner excludes Markdown-owned code/link/image/autolink/raw-HTML regions, merges source-ordered observations linearly, and retains no math index/parser/rendering state.

M109 stabilizes cross-cutting public contracts without widening source authority: immutable `Document`, `DocumentGraph`, `KnowledgeIndex`, `WorkspaceReport`, and prepared `ChangeSet` values support concurrent reads/use; `DocumentBuilder` remains caller-synchronized mutable state; graph/workspace resolvers are synchronous, serial within one call, and never retained; public sentinel failures are classified with `errors.Is`; structural selectors remain explicitly result-bounded; graph/workspace/knowledge work remains bounded by finite caller-provided document sets; and `Kind` remains the closed core structural namespace. The one source-level API cleanup replaces the ambiguous four-value workspace unresolved-reference tuple with typed immutable `UnresolvedReference` data.

M110 implements an explicitly opted-in, parser-backend-independent third-party read-only overlay. `ParseWithOptions` preserves the ordinary core parse, then invokes namespaced recognizers synchronously/serially over one immutable source string and retains only validated non-empty ranges plus scalar metadata under positive caller-owned total node/metadata limits. Extension observations remain separate from core `Kind`, core nodes, mutation, construction, graph, and parser internals; malformed output/errors/panics fail the complete call with `ErrInvalidExtension`. Marksplice bounds only retained observations and does not claim to sandbox ordinary caller-linked Go code.

Historically, M111 froze the complete internal parser-substitution surface as `parser.Backend`: one parser-independent `DocumentObservations` pass plus every construction-only blockquote/typed-inline/link/reference proof and reference-normalization primitive consumed by `internal/splice`. At that transition stage the production splice layer still used one temporary Goldmark bridge and a test-only differential harness compared independent immutable inputs. M115 later removed both transitional paths without changing the public API or source-ownership contract.

M112 implemented the Marksplice-native block layer under that frozen boundary. The candidate covered headings/paragraphs, lists/tasks, blockquotes, fenced/indented code, thematic breaks, HTML blocks, reference definitions, GFM tables, physical-line/indent semantics, and required container relationships; its transition-time exact block projection matched the then-temporary oracle on all 676 parser-applicable published GFM examples.

M113 completed the parsed-document inline/reference layer: code spans, emphasis/strong/strikethrough, direct/reference link and image ownership, autolinks, raw HTML, resolved/unresolved relationship facts, and full Unicode GFM reference-label folding. Native inline nodes and relationship projections matched the transition-time oracle on all 676 parser-applicable examples. Production still used the temporary bridge at M113; M115 later removed it. `golang.org/x/text v0.41.0` remains the direct parser-owned dependency for full Unicode case folding.

Existing-document mutations are prepared as minimal source-bound patches. Untouched bytes are not regenerated, prepared changes reject stale source, and operations fail closed when candidate parsing/source proof cannot preserve required invariants. `Document.ComposeChanges` can atomically combine independent opaque `ChangeSet` values already prepared against the same exact snapshot; source overlap, overlapping structural/link/footnote-relationship deltas, or a combined candidate that differs from the independently validated model fail closed. It does not expose raw patches or arbitrary byte batching. Marksplice does not use whole-document AST serialization as the ordinary edit path.

New-document construction is deliberately separate. `DocumentBuilder` may use deterministic canonical GFM because there is no pre-existing author formatting to preserve. Reviewed constructed blocks and the final document are reparsed and checked against requested semantic/source expectations before bytes are returned.

Semantic parsing is broader than the public actionable API. Unsupported or not-yet-reviewed shapes remain understandable/preservable rather than being exposed with guessed source ranges or mutation semantics.

The current production maintainability gate is cyclomatic complexity 15 or lower per function (`gocyclo -over 15` must be empty for production code), plus production and test-inclusive `unparam`. The post-M79 whole-code review established this stricter gate without changing public APIs, kind ordinals, `NodeID` derivation, generated bytes, source ownership, parser profile, or fail-closed behavior.

## Completed roadmap record

The completed roadmap is split into six ordered phases. The milestone numbers express the dependency order that was used, not permission to weaken a gate to keep numbering intact. Every completed slice preserves source ownership, stale-source rejection, deterministic construction, bounded resource use, parser isolation, and the production complexity gate.

Marksplice does **not** maintain a family of first-party syntax extensions. A broadly useful Markdown/document capability belongs in core when its contract is general enough. Dialect-specific or product-specific syntax stays outside core. M110 exposes a controlled read-only public SPI so independent Go packages can attach such semantics without becoming Marksplice dependencies or bypassing Marksplice safety invariants.

### Phase A — complete the single-document core

**M92 — Structured link/image label and alt composition — complete.** Typed construction now lets direct and full-reference link labels/image alt content use the already-reviewed bounded inline composition model. Destination/title/reference semantic proof remains independent from child-inline hierarchy proof, nested link/image/autolink/reference children remain rejected, and ambiguous delimiter hierarchies fail closed.

**M93 — Reference and autolink completion — complete.** Typed construction now supports parser-normalized collapsed/shortcut reference links/images, explicit deferred definitions plus full forward-reference constructors, and exact parser-proven bare/extended autolink tokens while preserving M89's prior-definition full-reference contract. Existing promoted single-line reference definitions can replace an existing title payload and can remove their complete physical line only when candidate proof preserves every surviving full/collapsed/shortcut/image reference relationship; ordinary parsed reference links/images remain non-promoted.

**M94 — Existing-source blockquote completion — complete.** Parsed snapshots now promote one complete top-level blockquote container across multiline, nested, lazy-continuation, marker-only, and multi-block forms only when exact physical ownership is proven. `Document.BlockquoteContentRanges` exposes caller-owned inner per-line spans; lazy markerless lines require parser semantic proof on that physical line, nested blockquotes remain internal children rather than receiving public identities, and complete-container removal strengthens survivor validation across the full blockquote mapping. Historical single-paragraph `ContentRange` and construction authorization remain unchanged.

**M95 — Structural mutation composition — complete.** `Document.ComposeChanges` atomically combines independent opaque prepared mutations only when every constituent is bound to the same exact snapshot. The source layer revalidates all private patches as one non-overlapping original-coordinate set; splice composes compact independently validated node/reference model deltas and proves one combined candidate. Overlapping patch/model regions, same logical aggregate edits, and cross-operation Markdown interactions fail closed; arbitrary raw byte-patch batching is not public.

**M96 — Single-document read/edit/create audit — complete.** The family-by-family audit closed two high-value gaps already supported by proven internal models: promoted inline links/reference definitions/autolinks expose existing parser-proven semantic scalar facts, and canonical GFM table construction accepts zero body rows under a complete `KindTable` construction expectation. Broader link relationships stay M99, generalized fenced-block ownership stays M103, and metadata generalization stays M106; no symmetry-only APIs were added.

### Phase B — document intelligence

**M97 — Structural query surface — complete.** `Document.QueryNodes` and `Document.QuerySections` provide caller-bounded source-ordered selection over the existing immutable node/section arrays. Node queries filter reviewed public kinds plus optional complete containment in a snapshot range; section queries filter levels plus optional complete subtree containment. Both require an explicit positive result limit, reject malformed/oversized filters, retain no query state, and add no persistent query index or second document model.

**M98 — Anchors, fragments, and TOC — complete.** GitHub-compatible heading anchors and deterministic duplicate allocation derive from parser-independent semantic heading text; fragments resolve exactly across heading-derived and promoted explicit HTML anchors; TOCs derive from the existing `Section` hierarchy; and synchronization is allowed only for an explicitly designated empty/strict TOC-shaped section body before reusing ordinary section-body candidate proof. No persistent navigation index or second tree is retained.

**M99 — Link intelligence — complete.** `Document.LinkRelationships` now exposes source-ordered immutable parser-resolved direct/reference link, image, and autolink relationships, including reference form/resolved destination/title, optional uniquely proven promoted definition ownership, optional existing promoted source-node identity, email classification, and M98-compatible local-fragment status/target. Valid relationships remain readable even when their source shape is outside ordinary edit promotion. Other-document paths/URLs remain opaque data, unresolved reference-looking source is not reinterpreted, and no filesystem/network authority or persistent relationship graph is added.

**M100 — Multi-document graph — complete.** `BuildDocumentGraph` now consumes only an explicit caller-provided set of immutable documents keyed by opaque `DocumentKey` values. Local `#fragment` relationships become self-edges without resolver involvement; every other M99 relationship is included only when the caller's build-only `DocumentResolver` maps it to a key already present in that set. Cross-document fragments reuse M98 targets, missing/ambiguous fragments keep the document edge without fabricating a target, adjacency stores edge indices rather than duplicate edge copies, and deterministic outgoing/backlink/reachability/related-document APIs perform no filesystem, path-normalization, network, or hidden discovery work.

**M101 — Workspace validation and repair planning — complete.** `ValidateWorkspace` consumes only the explicit caller document set and an optional build-time `WorkspaceResolver` whose `Ignore`/`Resolved`/`Missing` classification preserves the M100 authority boundary. It reports deterministic typed findings for local/cross-document missing/ambiguous/invalid fragments, caller-declared missing documents, conservative unresolved explicit full/collapsed references, root-relative orphan documents, and caller-designated managed TOCs. Source-bound findings expose `SourceDocument` plus exact offsets where available. The only automatic repair is source-preserving synchronization of recognized stale managed TOCs; multiple stale TOCs in one document are prepared atomically from the same snapshot through a family-specific validated multi-patch path rather than generic M95 composition.

### Phase C — broadly useful core capabilities inspired by ecosystem use cases

[`extension-strategy.md`](extension-strategy.md) records the feature ideas reviewed from the wider Markdown ecosystem. Those projects are idea sources only; Marksplice does not reproduce their extension model or adopt their packages as core architecture.

**M102 — Semantic block patterns — complete.** `Alert`/`AlertKind` recognize the exact reviewed GitHub alert markers (`NOTE`, `TIP`, `IMPORTANT`, `WARNING`, `CAUTION`) only on already-promoted top-level blockquotes and reuse the underlying blockquote identity/source range. `AlertBodyRanges` exposes the source-proven body segments after the marker line. `DocumentBuilder.AppendAlert`, `AppendAlertContent`, and `AppendAlertBlocks` produce canonical depth-1 alerts through the existing blockquote writer/proof path, while dedicated private construction intent prevents alerts from becoming nested blockquote/alert children. Recognition is call-local expected-linear work with no persistent alert index, parser extension, or new structural `Kind`.

**M103 — Fenced-block semantics — complete.** `FencedBlock` now exposes one complete source-proven top-level GFM fenced container: opening/optional closing delimiter ranges and lengths, indentation, parser-proven info string/language, complete container range, and caller-owned per-physical-line payload ranges. Empty and unclosed forms are represented without synthetic source. The historical `FencedCode` view remains the narrower contiguous payload-replacement capability, so broader readability does not create generic rewrite authority. `DocumentBuilder.AppendFencedCode` also supports canonical empty payloads. Technical payload names such as `mermaid`, `geojson`, `topojson`, `stl`, `math`, `d2`, or other languages remain opaque data values.

**M104 — Footnotes — complete.** Footnote references/definitions are now a core capability under an explicit exact, case-sensitive syntax/source contract. Top-level definitions are independently source-proven; parser-backed references expose definition identity and occurrence order; multiline semantic bodies are readable without gaining broad mutation authority; simple bodies support source-preserving replacement; rename atomically updates the definition plus every parser-bound reference; canonical immediate/deferred construction supports typed references; M95/M97 integrate the new relationship/kind; and links inside footnote bodies participate in M99/M100. The implementation uses an isolated temporary semantic pass rather than changing the normative GFM parser or exposing a first-party extension mode.

**M105 — Mathematical expressions — complete.** Marksplice now recognizes the reviewed GitHub-compatible `$...$`, dollar-backtick, one-line `$$...$$`, and exact-info `math` fenced forms while keeping the normative GFM parser unchanged. Dedicated forms are independently source-proven, queryable through appended `KindMathExpression`, and payload-editable only after same-style candidate proof; fenced math reuses M103 identity and historical edit authority. `MathInline`, `MathBacktickInline`, and `AppendMathBlock` provide deterministic construction, multiline math remains available through existing fenced construction, payload is opaque, and rendering engines stay outside core.

**M106 — Metadata/front-matter generalization audit — complete.** Envelope recognition is now independent from field editability. `Document.FrontMatter()` exposes exact immutable YAML/TOML envelope ownership for empty or conservatively metadata-evidenced source, including complex and duplicate-only metadata, while unsupported payload remains opaque. Existing simple-field mutation authority is unchanged, TOML table scope prevents nested members from being promoted as top-level fields, empty leading envelopes have explicit metadata precedence, and non-empty delimiter pairs without metadata evidence remain GFM. No YAML/TOML parser, serializer, metadata AST, schema, or new dependency is introduced.

**M107 — Knowledge-document primitives — complete.** `BuildKnowledgeIndex` is an immutable syntax-independent overlay on an already-authorized M100 `DocumentGraph`. Callers can supply exact case-sensitive aliases, tags, and direct logical references to existing `DocumentKey` targets; aliases are globally unique and cannot collide with canonical keys, logical references remain separate from source-backed M100 edges, and queries cover aliases, exact tags, logical outgoing/backlinks, plus combined reachability/related documents. No wikilink/hashtag/front-matter inference, dialect grammar, arbitrary metadata schema, source mutation, resolver retention, I/O, or second graph is introduced.
