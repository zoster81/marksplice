# M92 — Structured Link/Image Label and Alt Composition

## Status

Complete. Final documented-tree release-quality verification is green and recorded below.

## Objective

Extend existing typed link/image construction so direct and full-reference link labels and image alt content can reuse the bounded structured-inline composition established by M88, without widening ordinary parsed-source link/image editability and without coupling destination/title/reference semantic proof to child-inline hierarchy proof.

## Public contract

M92 adds no exported functions. It extends the existing constructors:

- `LinkInline`;
- `LinkInlineWithTitle`;
- `ImageInline`;
- `ImageInlineWithTitle`;
- `ReferenceLinkInline`;
- `ReferenceImageInline`.

Their label or alt children may now contain semantic text plus `CodeInline`, `EmphasisInline`, `StrongInline`, and `StrikethroughInline` under the same reviewed M88 nesting rules. Direct strikethrough-in-strikethrough remains rejected. Links, images, autolinks, and reference links/images remain invalid nested label/alt children.

The structured wrapper depth bound remains 64. Link/image ownership itself does not consume one wrapper level. Generated source is still accepted only when reparsing reproduces the requested hierarchy exactly, so delimiter combinations that are semantically ambiguous fail closed even below the maximum depth.

M89's full-reference contract is unchanged: the exact reference label must identify exactly one already-appended top-level reference definition. Collapsed references, shortcut references, forward definitions, and normalized-label lookup remain outside this milestone.

Existing text-only typed link/image byte output remains unchanged. Ordinary parsed-source link/image promotion and existing-document mutation contracts remain unchanged; a generated link/image with structured label or alt content is not thereby promoted as an editable ordinary parsed-source link/image.

## Requirements and edge cases

Destinations, titles, and reference labels retain their existing conservative validation. Empty labels/alt content, invalid UTF-8, unsafe title/reference syntax, ambiguous prior definitions, and malformed structured children fail before builder mutation.

Structured labels/alt content must preserve the M88 safety rules: bounded wrapper depth, adaptive code fences, delimiter alternation for nested emphasis-family wrappers, no direct nested strikethrough, and exact semantic hierarchy proof after reparsing.

The destination/title/reference semantic contract is deliberately independent from the child-inline hierarchy contract. A hierarchy match cannot authorize changed destination/title/reference semantics, and a semantic link/image match cannot authorize a different child hierarchy.

## Architecture and test strategy

M92 reuses the existing private `Inline` representation and writer. No second public inline AST is introduced.

Direct structured links/images produce two independent construction-only expectation families:

1. a direct link/image semantic expectation containing kind, syntax/label ranges, destination, title, and title-presence facts;
2. an inline hierarchy expectation containing only kind, syntax/content ranges, delimiter facts where applicable, and parent identity.

The direct semantic expectation crosses `internal/splice` into a parser-independent DTO under `internal/parser`. `internal/parser/goldmark` validates direct link/image kind, exact canonical source envelope, destination, title, and title presence without inspecting or authorizing the child hierarchy.

Full-reference links/images retain the M89 semantic expectation. M92 adds only a construction-only `StructuredLabel` fact so the M89 validator can prove full-reference type/value, exact reference source, and resolved destination/title semantics without requiring the label itself to be one plain-text node.

The hierarchy validator now permits a direct or full-reference link/image to be a construction-only owner of M88 structured children. Its expectation does not contain destination/title/reference semantics. For full references only, already-proved M89 reference expectations are supplied so the validator can synthesize ephemeral canonical definitions required for parsing the requested reference owner. Those definitions remain validation input only and are never emitted.

Goldmark link/image semantic extraction is shared between the direct and reference validators to avoid duplicate type switches. Ordinary `Adapter.Parse` observations, Marksplice source mappers, and mutation APIs are not changed.

Text-only direct links/images retain the historical parsed-snapshot expectation path rather than being forced through the new M92 direct semantic validator. This preserves their existing generated bytes and existing simple promotion behavior.

## TDD evidence

The initial public RED failed exactly on the pre-M92 writer guard `nested typed inline kind is not supported` for both direct and full-reference structured labels.

Permanent public tests prove:

- direct link labels containing mixed text, strong emphasis, and code;
- titled image alt content containing emphasis and strikethrough;
- full-reference link/image structured label/alt construction against exact prior definitions;
- exact generated bytes;
- ordinary `Parse` does not newly promote structured generated link/image nodes;
- wrapper depth 64 remains accepted inside a link label and depth 65 is rejected;
- nested link, image, autolink, and reference forms inside label/alt content remain rejected;
- existing text-only caller-slice snapshot behavior and unsafe destination/title/reference rejection remain green.

Direct Goldmark tests prove:

- structured direct link/image destination/title semantics independently from hierarchy proof;
- changed direct destination/title semantics are rejected;
- direct link/image and full-reference owners can own exact structured children in the hierarchy proof;
- changed child parentage is rejected independently from semantic link/image facts;
- structured full-reference labels retain exact full-reference type/value/resolved semantics.

## Devil's advocate review

1. **Construction support could accidentally widen existing-source link/image editability.** M92 changes no ordinary parser observations, source mappers, public detail accessors, or mutation APIs. A public regression test explicitly verifies structured generated link/image nodes are not promoted by ordinary `Parse`.
2. **Destination/title proof could become coupled to hierarchy proof and let one validator authorize the other's responsibility.** The final design uses separate direct semantic and hierarchy DTOs/validators; the hierarchy expectation contains no destination/title/reference fields. Full references retain the independent M89 semantic validator.
3. **Reference proof definitions could leak into output or loosen exact-definition ownership.** The existing exact prior-definition lookup remains mandatory, and proof definitions are synthesized only inside construction validation and are never emitted.
4. **Delimiter collisions or excessive recursion could change semantics.** M88's 64-wrapper maximum, delimiter policy, and exact reparsed parent/child/order proof are reused unchanged; ambiguous generated structures fail closed.
5. **Adding owner nodes could make hierarchy matching quadratic or inflate complexity.** Matching remains a bounded AST walk with anchor buckets and precomputed parent→children lists. Shared link/image semantic extraction removes duplicated branching, and the production `gocyclo <=15` plus both `unparam` gates remain green.

## Exit decision

M92 is functionally complete: structured direct/full-reference link labels and image alt content now reuse the bounded M88 composition model while semantic link/image/reference proof remains independent from hierarchy proof and ordinary parsed-source editability is unchanged. M93 reference and autolink completion is the next roadmap boundary.
