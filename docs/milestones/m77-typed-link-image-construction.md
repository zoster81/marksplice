# M77 — Typed Inline Link and Image Construction

## Status

Complete and green.

## Objective

Extend the M75–M76 construction-only `Inline` vocabulary with conservative source-proven inline links and images without changing the historical raw-GFM builder APIs or exposing Goldmark types.

## Public contract

```go
func LinkInline(destination string, label ...Inline) Inline
func ImageInline(destination string, alt ...Inline) Inline
```

Both values are construction-only. Their child slices are defensively copied. M77 accepts only `TextInline` children for link labels and image alt text; the variadic shape intentionally leaves room for separately reviewed structured-label composition later without changing the constructor signatures.

Destinations are written canonically as angle destinations:

```text
[label](<destination>)
![alt](<destination>)
```

The destination must be non-empty valid UTF-8 on one physical line, contain no NUL, and contain none of `<`, `>`, backslash, or `&`. That conservative boundary avoids GFM escape/entity interpretation so the caller-provided destination remains byte-identical to the source-proven destination. Titles are not generated by M77.

## Architecture and proof

M77 adds no parser field, persistent construction AST, or new source mapper. The typed writer reuses M75 semantic-text escaping for every label/alt child, records the exact generated label/alt and destination ranges, then reparses the standalone inline candidate through the ordinary public snapshot boundary.

The proof requires:

- exactly one enclosing paragraph for the complete rendered inline candidate;
- a promoted/source-proven `KindInlineLink` or `KindImage` at each requested position;
- the exact destination range;
- the exact source-mapped label/alt range retained by the existing M7/M11 mappings;
- angle-destination ownership;
- no title;
- for links, the parser semantic destination must equal the caller value;
- for images, whose Goldmark public observation does not expose the semantic destination, the existing source mapping plus the no-escape/entity destination policy provides the conservative byte-exact boundary.

Unexpected promoted inline kinds or any range/shape disagreement fail with `ErrInvalidConstruction`.

## Risks and mitigations

1. **Destination normalization could make caller intent differ from generated semantics.** M77 writes only angle destinations and rejects syntax that would require GFM escaping/entity interpretation; link reparsing additionally compares Goldmark's semantic destination with the exact requested value.
2. **Image destination semantics are less observable through Goldmark's public image API.** M77 does not inspect Goldmark private fields. It instead requires the established Marksplice `ImageMapping`, exact lexical destination ownership, and the stricter no-normalization destination policy.
3. **Structured labels could create ambiguous nesting or new public nodes.** M77 accepts only `TextInline` children and the standalone candidate proof rejects unexpected promoted kinds.
4. **Caller mutation of a child slice could change retained construction intent.** Constructors deep-copy the supplied `Inline` children.
