# M89 — Typed Full-Reference Link and Image Construction

## Status

Complete and green.

## Objective

Extend the existing construction-only `Inline` intent with conservative GFM full-reference link and image forms while preserving the ordinary parsed-source link/image API and avoiding a second public inline AST.

## Public contract

M89 adds:

```go
func ReferenceLinkInline(reference string, label ...Inline) Inline
func ReferenceImageInline(reference string, alt ...Inline) Inline
```

The generated forms are exactly:

```text
[label][reference]
![alt][reference]
```

The reference label must match exactly one already-appended top-level reference definition in the destination `DocumentBuilder` by exact string. The matching definition supplies the resolved destination, title, and title-presence semantics used by construction proof.

M89 deliberately excludes:

- forward references to definitions appended later;
- collapsed references such as `[label][]`;
- shortcut references such as `[label]`;
- case-normalized or whitespace-normalized definition lookup;
- structured typed label/alt children beyond `TextInline`;
- reference forms nested inside M88 structured emphasis/strong/strikethrough wrappers;
- any widening of ordinary parsed-source reference-link/image promotion or mutation.

Reference labels must be non-empty, valid UTF-8, single-line, NUL-free, and must not require bracket, backslash, or entity interpretation.

## Requirements and edge cases

The design must distinguish semantic GFM reference resolution from Marksplice construction authority. Goldmark resolves reference labels using GFM normalization rules, including case normalization, but M89 intentionally requires an exact builder-definition label so construction does not silently target a different human-visible definition spelling.

A missing, duplicate exact, differently-cased, unsafe, or not-yet-appended reference definition fails with `ErrInvalidConstruction` before builder mutation. The destination builder remains unchanged after rejection.

## Architecture and test strategy

The existing typed-inline render path becomes builder-aware so it can inspect already-retained construction blocks. The public `Inline` value gains only private reference intent; no persistent parsed-document reference model is introduced.

For a reference link/image, the writer:

1. validates semantic-text-only label/alt children;
2. validates the requested exact reference label;
3. locates exactly one already-retained `constructionReferenceDefinition` with that exact label;
4. writes canonical full-reference source;
5. records an ephemeral construction-only expectation containing kind, syntax range, label range, reference range, exact reference value, resolved destination/title, and title presence.

The expectation crosses `internal/splice` into a parser-independent DTO under `internal/parser`. `internal/parser/goldmark` is the only package that interprets it through Goldmark AST nodes.

Goldmark reference resolution requires definitions in the parsed document, so the validator creates an ephemeral proof source consisting of the requested inline candidate followed by canonical definitions derived from the already-reviewed builder facts. Those proof definitions are validation input only and are never emitted into the requested block or retained builder source.

Validation requires:

- the proof root to preserve one exact first-line paragraph range matching the original inline candidate;
- the exact count/kind/anchor of requested link/image reference nodes;
- `ast.ReferenceLinkFull` rather than collapsed/shortcut syntax;
- exact `Reference.Value` bytes;
- exact label and reference source ranges;
- destination/title/title-presence semantics resolved from the definition.

Ordinary `Adapter.Parse`, public link/image accessors, source mappers, and mutation APIs are unchanged.

## TDD evidence

The initial public RED failed only because `ReferenceLinkInline` and `ReferenceImageInline` did not yet exist.

Permanent public tests cover:

- full reference link and image construction;
- titled and untitled definitions;
- exact generated bytes;
- missing definition rejection;
- exact-label case mismatch rejection even though Goldmark can normalize labels;
- duplicate exact definition rejection;
- unsafe reference-label rejection;
- structured label/alt rejection;
- use through paragraph, heading, blockquote, and nested-blockquote typed entrypoints;
- no unintended parsed-source public reference promotion.

Direct Goldmark tests cover exact full link/image proof, non-full/changed reference source rejection, and conflicting resolved-definition semantics.

A temporary diagnostic test confirmed Goldmark exposes full/collapsed/shortcut reference types distinctly and resolves destination/title from definitions. The diagnostic file was removed after the contract was established.

## Devil's advocate review

1. **Goldmark normalization could bind construction to a differently spelled definition.** The builder performs exact-string lookup before Goldmark proof; case-normalized matches are rejected.
2. **Forward references could make append-time validation depend on future builder state.** M89 requires the definition to exist before the reference inline is appended, keeping every append immediately and deterministically verifiable.
3. **Duplicate exact definitions could make construction resolution ambiguous.** M89 requires exactly one matching retained definition and fails closed otherwise.
4. **Proof definitions could accidentally leak into generated output.** They are created only in the Goldmark validation helper; the writer retains/emits only the caller-requested full-reference token.
5. **Construction support could widen existing-source editability.** All new semantic proof is construction-only; ordinary observations and mutation contracts are unchanged.
6. **Validation complexity could regress maintainability.** The initial input validator measured cyclomatic complexity 22 and was split into kind/prefix, range, and syntax helpers. The production `gocyclo -over 15` gate is green after refactor.

## Exit decision

M89 completes the first typed reference-style construction slice with exact prior-definition ownership and no existing-source API widening. Forward, collapsed, shortcut, normalized-label, structured-label/alt, and broader autolink forms remain separate future reviews.
