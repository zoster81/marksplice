# Goldmark GFM Capability and Ownership Matrix

Status: source of truth for the parser/source-preservation ownership boundary established by M1 under Marksplice's single GitHub Flavored Markdown (GFM) profile.

Exact dependency versions belong in `go.mod` and `go.sum`; this document records responsibilities, not version pins.

## Goldmark exit and ecosystem-idea boundary

Goldmark is the current temporary semantic parser and will be removed at M115 after the Marksplice-native CommonMark/GFM parser passes the required parity, conformance, fuzz, resource, performance, and maintainability gates. No Goldmark upgrade or migration belongs to the roadmap.

The external ecosystem catalog is evaluated in [`extension-strategy.md`](extension-strategy.md) only as a source of product ideas. Marksplice does not reproduce a first-party extension collection. Broadly useful concepts may become ordinary core capabilities through explicit review; dialect-specific syntax stays outside core and may later be implemented by independent Go packages through the M110 SPI.

The Goldmark exit is evidence-gated but mandatory: M111 freezes the parser contract/differential harness, M112 implements native block parsing, M113 native inline parsing, M114 proves full native conformance/hardening, and M115 removes Goldmark from active implementation and dependency paths.

## Evidence rules established by M1

A construct is not considered losslessly supported merely because Goldmark parses it. Evidence for a source-preserving capability must show the exact source region needed for the operation, byte preservation outside changed spans, deterministic behavior for unsafe or ambiguous mutation cases, and no unresolved semantic mismatch against the approved GFM contract.

The current implementation still uses Goldmark only as the temporary backend. The normative source hierarchy, approved snapshot, exact conformance evidence, advisory-source policy, and update procedure are owned by [`gfm-conformance.md`](gfm-conformance.md); do not duplicate or reinterpret them here. M111–M115 own the staged native-parser replacement and mandatory dependency removal.

While Goldmark remains the temporary backend, its semantic parser profile stays exactly GFM-oriented: `extension.GFM` plus only narrowly scoped compatibility behavior required to implement the published GFM syntax. Goldmark's additional packages do not define Marksplice core features. Future third-party dialect syntax, if any, belongs behind the explicit M110 opt-in SPI rather than the temporary Goldmark adapter.

Where Goldmark source positions are insufficient, Marksplice may add a bounded lexical scan tied to the semantic node and source snapshot. Such scans must stay internal and must not copy or fork Goldmark implementation code.
