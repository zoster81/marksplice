## Goldmark exit and ecosystem-idea boundary

Goldmark is the current temporary semantic parser and will be removed at M115 after the Marksplice-native CommonMark/GFM parser passes the required parity, conformance, fuzz, resource, performance, and maintainability gates. No Goldmark upgrade or migration belongs to the roadmap.

The external ecosystem catalog is evaluated in [`extension-strategy.md`](extension-strategy.md) only as a source of product ideas. Marksplice does not reproduce a first-party extension collection. Broadly useful concepts may become ordinary core capabilities through explicit review; dialect-specific syntax stays outside core and may be recognized by independent Go packages through the explicit M110 read-only SPI.

The Goldmark exit is evidence-gated but mandatory: M111 freezes the parser contract/differential harness, M112 completes native block parsing, and M113 completes native inline/reference parsed-document observations. M114 now owns the complete native backend/conformance/hardening gate; M115 removes Goldmark from active implementation and dependency paths.

## Evidence rules established by M1

A construct is not considered losslessly supported merely because Goldmark parses it. Evidence for a source-preserving capability must show the exact source region needed for the operation, byte preservation outside changed spans, deterministic behavior for unsafe or ambiguous mutation cases, and no unresolved semantic mismatch against the approved GFM contract.

The current implementation still uses Goldmark only as the temporary production backend, through the M111 `parser.Backend` substitution boundary. The test-only differential harness and conformance gate share the same approved GFM snapshot loader and compare Goldmark against the native candidate without retaining parser state. M112 completes the block layer and M113 completes the parsed-document inline/reference layer; block, inline-node, and link/reference relationship projections each match all 676 parser-applicable examples. M114 owns complete native `parser.Backend` construction-proof parity plus hardening, and M115 owns cutover and mandatory Goldmark dependency removal. The normative source hierarchy, approved snapshot, exact conformance evidence, advisory-source policy, and update procedure are owned by [`gfm-conformance.md`](gfm-conformance.md); do not duplicate or reinterpret them here.

While Goldmark remains the temporary backend, the normative semantic parser profile stays exactly GFM-oriented: `extension.GFM` plus only narrowly scoped compatibility behavior required to implement the published GFM syntax. M104 is the explicit adapter-orchestration exception: one separate Footnote-enabled parser instance acts only as a temporary semantic oracle for the reviewed Marksplice core footnote contract and is reconciled into Marksplice-owned observations before the snapshot is built. M105 does not add another parser instance or enable a Goldmark math extension: mathematical semantics are a Marksplice-owned bounded overlay over ordinary GFM observations plus independent source proof. M107 knowledge aliases, tags, and logical references are entirely caller-supplied above the M100 graph and have no Goldmark/parser/source-observation role. Goldmark's other additional packages do not define Marksplice core features. Third-party dialect observations use the explicit M110 opt-in read-only overlay above the completed core parse rather than the temporary Goldmark adapter; no extension API exposes Goldmark types or parser hooks.

Where Goldmark source positions are insufficient, Marksplice may add a bounded lexical scan tied to the semantic node and source snapshot. M103's fenced-code decorator is limited to preserving Goldmark's opening position before independent Marksplice proof; it does not turn a parser position into source ownership. Such scans/decorators must stay internal and must not copy or fork Goldmark implementation code.
